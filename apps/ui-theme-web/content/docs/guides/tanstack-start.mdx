## Install

Use an existing TanStack Start application.

```sh
npm install uitheme-web@latest
```

## Apply the appearance before hydration

Put the theme script in your root document's head. Keep your existing `HeadContent`, `Scripts`, and route setup.

```tsx
import { TanStackStartThemeScript } from 'uitheme-web/react';

<head>
  <TanStackStartThemeScript defaultTheme="system" systemThemeMode="js" />
  <HeadContent />
</head>;
```

Add `suppressHydrationWarning` to the root `html` element. Wrap your route content in the matching provider:

```tsx
import { TanStackUIThemeProvider } from 'uitheme-web/react';

<TanStackUIThemeProvider defaultTheme="system" systemThemeMode="js">
  <Outlet />
</TanStackUIThemeProvider>;
```

Use the same theme options and storage keys for the script and provider.

### System theme mode

Pass the same `systemThemeMode` to the script and the provider. The two have different defaults: the script uses `"js"` and the provider uses `"css"`.

| Value   | Classes on `<html>` for the `system` theme                                       | CSS that you need                                                                                                                                                         |
| ------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `"js"`  | `dark` when the system appearance is dark. No class when it is light.            | Dark tokens on `.dark` only.                                                                                                                                              |
| `"css"` | `system`. The `dark` class is not set, and the `color-scheme` style stays empty. | Dark tokens on `.dark`, and the same tokens on `.system` inside `@media (prefers-color-scheme: dark)`. Your `dark` variant must also match `.system` in that media query. |

For a saved `light` or `dark` theme, both values set or remove the `dark` class. Add your appearance and palette CSS, then use the [React controls](/docs/guides/react#add-styles-and-controls).

## Provider options

`TanStackUIThemeProvider` accepts these options.

| Prop                        | Default | Behavior                                                                                                                                  |
| --------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `disableTransitionOnChange` | `false` | When `true`, `setTheme` and `setColorTheme` switch off CSS transitions for the change. The provider restores them right after the change. |
| `nonce`                     | none    | Sets the `nonce` on every `<style>` element that the library injects. Use it with a `style-src 'nonce-…'` Content Security Policy.        |

`TanStackStartThemeScript` also accepts `nonce`. It sets the `nonce` on the inline script. Pass the same value to the script and to the provider.

```tsx
<TanStackUIThemeProvider nonce={nonce} disableTransitionOnChange>
  <Outlet />
</TanStackUIThemeProvider>
```

## Render from a saved cookie

Choose cookie-based rendering when the server must know the saved preference. The helpers in `uitheme-web/tanstack` build the initial theme data, HTML attributes, and bootstrap script.

Create theme data separately for each request. Read and write cookies through your server functions. Pass the returned initial values to the provider and connect preference-change callbacks to your persistence code.

Start from the working server example below rather than sharing mutable theme state between requests. Check two requests with different cookies and reload each appearance.
