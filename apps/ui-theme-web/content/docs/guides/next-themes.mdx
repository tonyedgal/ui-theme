## Who this guide is for

Use this guide if your app imports `next-themes` and you want UI-Theme instead.
It applies to Next.js, TanStack Start, and Vite React apps.
The `init` command does not look for `next-themes` in Vue or Nuxt apps.

The [CLI](/docs/cli#init) links to this page when `init` finds `next-themes`.

## What init does

`uitheme-cli init` looks for `next-themes` in the `package.json` of the app and in
its source files. If it finds it, `init` asks what to do:

```text
Replace next-themes with UI-Theme? [Y/n/c]
```

| Choice | Name    | Result                                                                                                            |
| ------ | ------- | ----------------------------------------------------------------------------------------------------------------- |
| `Y`    | Replace | Rewrites the provider and every `useTheme` import. Then removes the `next-themes` package. This is the default.   |
| `n`    | Keep    | Leaves `next-themes` and your source files alone. You set up the UI-Theme provider yourself.                      |
| `c`    | Create  | Keeps `next-themes`. Writes the UI-Theme provider to a separate file. You add that provider to your app yourself. |

Press Enter to accept the default, `Y`.

`init` does not ask in these cases. It uses `replace`.

- You pass `--yes`.
- You pass `--dry-run`.
- The run has no terminal, for example in CI.

Use `--next-themes` to choose without a question:

```sh
npx uitheme-cli init --next-themes replace
npx uitheme-cli init --next-themes keep
npx uitheme-cli init --next-themes create
```

The flag takes `replace`, `keep`, or `create`. Any other value is an error.
The flag has no effect when the app does not use `next-themes`.

Preview the result before you apply it:

```sh
npx uitheme-cli init --dry-run
npx uitheme-cli init --dry-run --next-themes create
```

The plan lists the files to change and the line `next-themes: <choice>`.
When `init` removes the package, the plan also shows the removal command.

In all three choices, `init` still sets up the theme CSS and `uitheme.json`.
It also installs `uitheme-web`.

### Replace

With `replace`, `init` rewrites your files, then removes the package.

1. It changes the imports from `next-themes`. See [what the rewrite changes](#what-the-rewrite-changes).
2. It changes the props of your `ThemeProvider`.
3. It checks every use of `useTheme`.
4. It writes the changed files, the CSS, and `uitheme.json`.
5. It removes `next-themes` with the package manager of the app.

`init` removes the package only when `dependencies`, `devDependencies`, or
`optionalDependencies` in `package.json` list it. If the package is listed but no
source file imports it, `init` only removes the package.

If the removal fails, `init` prints the command to run. It then exits with code `2`.

### Keep

With `keep`, `init` does not touch `next-themes`. It prints a link to the
[manual setup](#manual-setup) and exits with code `2`, because a step remains for you.

### Create

With `create`, `init` writes a provider file. The file exports `AppUIThemeProvider`.

- The file is `ui-theme-provider.tsx`, or `ui-theme-provider.jsx` for a JavaScript app.
- It goes in the folder above your installed controls, for example `components/`.
  If that folder is not inside the app, it goes in `components/` in the app.
- If a different file already has that name, `init` uses `ui-theme-provider-2`,
  then `ui-theme-provider-3`, and so on.

For Next.js, the file starts with `'use client'` and wraps `NextUIThemeProvider`
from `uitheme-web/next`. For TanStack Start and Vite React, it wraps `UIThemeProvider`
from `uitheme-web/react`. The provider sets `defaultTheme="system"` and one color theme,
`default`.

`init` does not add the file to your layout. Do that yourself. Then `init` exits with
code `2`. See [manual setup](#manual-setup).

## What the rewrite changes

The rewrite works on the files in the app that mention `next-themes`.
It skips `node_modules`, `.next`, `.git`, `.turbo`, `.vercel`, `.output`, `dist`, `build`,
`out`, `coverage`, and symbolic links.

### Imports

`init` replaces the import from `next-themes` with an import from UI-Theme.
It keeps your local names, so the rest of the file does not change.

| `next-themes`        | Next.js                    | TanStack Start and Vite React |
| -------------------- | -------------------------- | ----------------------------- |
| `ThemeProvider`      | `NextUIThemeProvider`      | `UIThemeProvider`             |
| `useTheme`           | `useNextUITheme`           | `useUITheme`                  |
| `ThemeProviderProps` | `NextUIThemeProviderProps` | `UIThemeProviderProps`        |
| Import path          | `uitheme-web/next`         | `uitheme-web/react`           |

A file that has `import { useTheme } from 'next-themes'` gets this line:

```tsx
import { useNextUITheme as useTheme } from 'uitheme-web/next';
```

### Prop mapping

`init` maps these props of the `next-themes` provider.

| Prop                        | Result                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `attribute="class"`         | Removed. UI-Theme uses `class` by default.                                                                                           |
| `attribute="data-theme"`    | Next.js only. Kept. In other frameworks, `init` stops.                                                                               |
| No `attribute`              | Next.js: `init` adds `attribute="data-theme"`, because `next-themes` uses that attribute by default. Other frameworks: `init` stops. |
| `defaultTheme`              | Kept. The value must be `light`, `dark`, or `system`.                                                                                |
| `enableSystem`              | Removed. See `themes`.                                                                                                               |
| `enableColorScheme`         | Removed. `enableColorScheme={false}` stops `init`.                                                                                   |
| `themes`                    | Rewritten. It may list only `light` and `dark`. `init` adds `system` unless you set `enableSystem={false}`.                          |
| `disableTransitionOnChange` | Kept. `disableTransitionOnChange={false}` is removed.                                                                                |
| `storageKey`, `nonce`       | Kept.                                                                                                                                |

With `enableSystem={false}`, `init` also adds `themes={['light', 'dark']}` and
`defaultTheme="light"` when your provider does not set them.

`init` stops on any other prop, on a prop spread, and on a computed value such as
`enableSystem={flag}`.

### Hook calls

`init` checks each call of `useTheme`. UI-Theme returns `theme`, `setTheme`,
`resolvedTheme`, `systemTheme`, and `themes`, plus other members that `next-themes`
does not have. `init` accepts calls that use only the five members.

`init` stops when your code does any of these:

- It uses `forcedTheme` or another member that UI-Theme does not return.
- It passes a function to `setTheme`.
- It passes a theme other than `light`, `dark`, or `system` to `setTheme`.
- It uses the whole result as an object, or uses `useTheme` as a value.
- It calls `useTheme` without assigning the result.

### Provider wrappers

Many apps wrap the provider in their own component. `init` supports one wrapper when
all of these are true:

- The component is a named export.
- It returns the provider and nothing else.
- Its only prop on the provider is `{...props}`, spread from its own rest parameter.

`init` then applies the prop mapping to the props at the one place where the app
renders the wrapper.

### The package

`init` removes `next-themes` with the package manager that it detected: `npm`,
`pnpm`, `yarn`, or `bun`. The command appears in the plan. If `package.json` does
not list the package, `init` does not remove it and tells you so.

## When init does not rewrite

The rewrite is all or nothing. If one file has a form that `init` cannot convert,
`init` changes no file. It prints the file and line, the form, and a link to
this guide. It then asks a different question:

```text
Create the UI-Theme provider as a separate file? [c/N]
```

Press `c` to create the separate provider file. Press Enter, or `n`, to keep
`next-themes` and set up UI-Theme yourself. With `--yes`, without a terminal, or with
`--next-themes replace`, `init` stops with an error and changes no file. Use
`--next-themes keep` or `--next-themes create` in scripts.

`init` stops for the cases below. Each message links to the section named here.

### Provider shape

- A bare import, such as `import 'next-themes'`.
- A default or namespace import.
- No `ThemeProvider` from `next-themes` in the app. For example, the app imports only `useTheme`.
- A second `ThemeProvider`, or a second use of the wrapper.
- A `ThemeProvider` that is conditional, or that appears outside JSX.
- A wrapper with extra logic, a props spread other than the rest parameter, or an unnamed export.
- A file with a syntax error.
- A file that still contains the text `next-themes` after the rewrite, for example in a comment.

### Provider props

- A prop that the prop mapping does not list.
- A computed prop value, or a props spread.
- `attribute` with a value other than `class` or `data-theme`.
- A missing `attribute` or `attribute="data-theme"` outside Next.js.
- A `defaultTheme` that is not `light`, `dark`, or `system`.
- `themes` with a value other than `light` and `dark`.

### useTheme

- An import other than `ThemeProvider`, `useTheme`, or `ThemeProviderProps`.
- A use of `next-themes` outside a plain import: `require`, a dynamic import, a re-export, a mock, or a config file.
- The forms in the hook call list above.

## Manual setup

Use these steps after `keep` or `create`, or when `init` stops.

1. Install the runtime:

   ```sh
   npm install uitheme-web@latest
   ```

2. Change the import. In Next.js, import from `uitheme-web/next`. In other React apps, import from `uitheme-web/react`.

   ```tsx
   // before
   import { ThemeProvider, useTheme } from 'next-themes';

   // after, Next.js
   import { NextUIThemeProvider, useNextUITheme } from 'uitheme-web/next';
   ```

3. Change the provider props. Use the [prop mapping](#prop-mapping). In Next.js, a `class` setup needs no `attribute` prop. A `data-theme` setup needs `attribute="data-theme"`.

   ```tsx
   <NextUIThemeProvider defaultTheme="system">{children}</NextUIThemeProvider>
   ```

4. Rename each `useTheme` call to `useNextUITheme` (Next.js) or `useUITheme` (other React apps). Keep the call inside the provider.

5. If you chose `create`, import `AppUIThemeProvider` from the new file and render it in place of your old provider.

6. Keep `suppressHydrationWarning` on the `html` element in Next.js. See the [Next.js guide](/docs/guides/nextjs).

7. Test the first page load, a reload with a saved theme, and a change of the system appearance.

8. Remove the old package:

   ```sh
   npm uninstall next-themes
   ```

Use only one theme provider to control the appearance of the page at a time.

## Differences from next-themes

- `useTheme` outside a provider throws an error: `useUITheme must be used within a UIThemeProvider`, or the matching message for `useNextUITheme`. In `next-themes` version 0.4.6, the hook returns an empty default object in the same case.
- A theme is `light`, `dark`, or `system`. For more looks, use [color themes](/docs/installation#tailwind-and-palettes) with `colorThemes` and `setColorTheme`.
- UI-Theme has no `forcedTheme` and no `value` prop. `setTheme` takes a theme, not a function.
- UI-Theme animates a theme change with `switchTheme`. `setTheme` changes the theme at once. See the [React guide](/docs/guides/react#change-the-theme).
- The Next.js provider uses the `class` attribute by default. `next-themes` uses `data-theme`.
- UI-Theme sets the `color-scheme` style on the `html` element by itself, so it has no `enableColorScheme` prop.
- UI-Theme has `disableTransitionOnChange` and `nonce` props. See the [Next.js guide](/docs/guides/nextjs#provider-options).
